## Findings fixed in this phase

1. **Existence oracle on deletes.** `DELETE` of an id that does not exist answered 204 ("deleting twice is fine"), the same id hidden by permissions 404:
   anybody could tell whether a board, column, label, comment, task, notebook, category or page id exists. A deleted label even answered 204 without
   any permission check. Now a missing id answers the same 404 as a hidden one; a second delete of something in the trash still succeeds (it is
   still there). In the sync batch both are `ok` (an offline device resends its outbox without being told off; nothing hidden is touched, the check
   comes first). The web no longer reports a `not_found` delete or restore of something another device purged.
2. **Two different 404 bodies.** Some services threw `new NotFoundException()` (`{"message":"Not Found"}`), the permission checks the tree's
   `not_found` (`{"message":"not_found","error":"Not Found"}`), sometimes both within one route (share links, page snapshots): the body told hidden
   and missing apart. A global `NotFoundFilter` gives every bare 404 the one canonical body (also its key order).
3. **Not-found messages that said what was missing** (`notebook`, `category`, `column`, `parent`): creating a page in a hidden category and in a
   missing one answered differently. They all say `not_found` now.
4. **Unknown fields were dropped silently** (mass assignment was prevented, but a client never learned a field was ignored, and a forged field
   looked accepted). They are refused now (bodies, query strings, socket payloads). Sync operations keep dropping unknown fields: refusing would
   throw away offline work for a harmless extra field, and nothing unknown is ever applied.
5. **Two devices replacing a page's text from the same version** could both succeed (the removed `PUT /pages/:id/content` refused the second).
   The replacement takes a per-page lock on the instance (see "Accepted" for several instances).
6. **Placeholder secrets** started in production. Refused now (see above), and `METRICS_TOKEN` (new) must have 32+ characters.
7. **Logs** could carry media tokens (`?t=`), link sessions (`?s=`), invite tokens and feed secrets in request paths and in error messages of
   outside calendars and push services. Every log line is scrubbed (`AppLogger`), request lines carry the path without its query string.

## Accepted (not changed), with the reason

- **Rate limits are per instance** (the throttler keeps its counters in memory). With several instances behind a load balancer each counts on its own,
  so the effective limit is the limit times the instances. Acceptable for the sizes this release targets; a Redis-backed throttler storage is the fix.
  `RATE_LIMIT_FACTOR` scales every limit.
- **The share-link password counter and the page-replace lock are per instance** for the same reason.
- **Media tokens travel in the query string** (`<img>`/`<video>` cannot send headers). They live 15 minutes, are bound to one person, and are scrubbed
  from logs; the media answer sets `Referrer-Policy: no-referrer`.
- **`/api/health` is public** and reports which part is degraded (no versions, addresses or counts).
- **Instance administrators see account emails** (Administration → accounts): that is their job.
- **Account deletion** does not exist in 1.0 (decided here, see `phase-17.md`); content a person wrote stays with their account.
